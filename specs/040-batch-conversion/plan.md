# Implementation Plan: Batch Conversion

**Branch**: `040-batch-conversion` | **Date**: 2026-03-10 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/040-batch-conversion/spec.md`

## Summary

Extend `forge convert` to accept multiple input file paths, process them in parallel via `rayon::par_iter()`, and produce an aggregated status summary on stderr. The existing single-file pipeline is wrapped — never modified. New `batch` module handles orchestration, output naming, and status formatting. Single-file backward compatibility is preserved: one input = existing behavior.

## Technical Context

**Language/Version**: Rust, Edition 2024, stable 1.93.0
**Primary Dependencies**: clap 4.x (derive), serde 1.0.228, thiserror 2.0.18, rayon (new — MIT/Apache-2.0)
**Storage**: Local filesystem (read input .md files, write OSCAL JSON/XML/YAML output files)
**Testing**: cargo test (unit + integration), insta 1.46.3 (snapshots), tempfile 3.25.0, criterion 0.8.2 (benchmarks)
**Target Platform**: Local CLI (macOS, Linux)
**Project Type**: Single Rust crate (binary + library)
**Performance Goals**: Batch of 10 files completes in ≤50% of sequential time (2x speedup minimum)
**Constraints**: `--jobs` range 1–256; warn at >100 files; follow symlinks silently
**Scale/Scope**: Typical batch: 5–50 files; max practical: hundreds
