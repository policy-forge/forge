## HIGH Findings

### H-1: Immutability violation in citation extraction
- **File**: `src/citation.rs:95`
- **Issue**: `extract_citations` mutates `PolicyRequirement.text` in place, stripping citations and normalizing prose. Violates immutability coding standard and creates hidden side effects.
- **Fix**: Return a new `PolicyRequirement` with updated text instead of mutating.

### H-2: Citation ID collision on missing stable_id
- **File**: `src/citation.rs:82-88`
- **Issue**: Falls back to empty string when `stable_id` is missing, causing multiple requirements without IDs to generate identical citation IDs. Silent data corruption.
- **Fix**: Return an error instead of proceeding with empty string.

### H-3: Pipeline uses mutation instead of functional transformation
- **File**: `src/pipeline.rs:84-88`
- **Issue**: `assign_stable_ids` and `extract_citations` take `&mut` references instead of consuming and returning new values, contradicting the documented "functional transformation" ownership pattern.
- **Fix**: Refactor to consume ownership and return enriched instances.

### H-4: Unbounded recursive citation collection (DoS risk)
- **File**: `src/oscal/component_definition.rs:235-249`
- **Issue**: `collect_citations_from_section` recursively walks section tree accumulating citations with no depth or count limit. Malicious input could cause OOM.
- **Fix**: Add `MAX_SECTION_DEPTH` (50) and `MAX_CITATIONS` (10,000) bounds.

### H-5: Missing input validation in encode_href_path
- **File**: `src/oscal/trace_embedding.rs:40-42`
- **Issue**: No path length validation. If input already contains `%25`, the encoding produces incorrect double-encoded output.
- **Fix**: Add length validation (4096 chars max) and handle pre-encoded input.

### H-6: Confusing bool-to-usize in pointer_to_json_path
- **File**: `src/validate/formatter.rs:41-42`
- **Issue**: `usize::from(segments.first() == Some(&""))` is needlessly obscure.
- **Fix**: Replace with `if segments.first() == Some(&"") { 1 } else { 0 }`.

### H-7: No property-based testing for parsing logic — FIXED
- **File**: `tests/property_tests.rs` (new, 14 property tests)
- **Issue**: Atomization and citation extraction have complex regex/string splitting logic with 0 proptest coverage. Prime candidates for property-based testing.
- **Fix**: Added `proptest` dev-dependency and 14 property tests (P-1 through P-14) covering invariants for `atomize_requirement()` and `extract_citations_from_text()`.

### H-8: Weak assertions in pipeline integration tests — FIXED
- **Files**: `tests/catalog_pipeline_test.rs`, `tests/component_pipeline_test.rs`
- **Issue**: Tests check "non-empty" instead of exact group counts or specific control IDs. Tests pass even if the pipeline drops entire sections.
- **Fix**: Replaced 5 weak `.is_empty()` assertions with exact counts (4 groups, 14 controls, 14 implemented-requirements) and structural checks.

### H-9: No concurrent test execution safety verification — FIXED
- **File**: `tests/concurrent_safety_test.rs` (new, 5 tests)
- **Issue**: Tests use `TempDir` for isolation but no explicit verification that parallel execution is safe (no global state, no environment variable races).
- **Fix**: Added 5 concurrent tests (C-1 through C-5) including a 32-thread barrier-synchronized stress test verifying atomization, citation extraction, and ID assignment under concurrent load.
