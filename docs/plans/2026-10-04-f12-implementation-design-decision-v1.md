# F12 portable review implementation decision

The completion plan requires an approved first workflow and asserted identity/quorum boundary before F12 implementation ([plan, line 109](/Users/bluby/repos/forge/docs/plans/2026-10-01-roadmap-completion-tranches.md:109)). The following proposal makes that prerequisite concrete. It approves an engineering contract; it supplies no participant, lawful source, named reviewer, authenticated human or product acceptance.

1. Start with re-review of explicitly selected **Approved/current native Mapping assertions** with complete captured source/dependency/lifecycle validation. Add recorded applicability decisions second under their independent current native closure. Schema validity and native `complete` never substitute for recorded approval. Draft/unapproved source promotion remains outside this first adapter.
2. Queue reviewer keys, roles, authors and times are **asserted-only**. A closed caller-selected policy specifies positive required approval seats, eligible declared keys/roles and explicit substitution edges. One distinct eligible approving key fills at most one seat. Declared author keys cannot review their own items. Abstention never lowers the approval denominator; rejection or changes-requested blocks a clean quorum. Distinct keys are not proof of distinct people or organizations.
3. Preserve all exact response bytes and differing dispositions. Exact same-identity/same-byte duplicates count once; same identity/different bytes refuses a validated bundle. Divergent live votes remain conflict, without a timestamp/file-order winner. Only explicit bound self-supersession retires a prior response. Use UTC seconds, explicit `as_of`, responses strictly before `due_at`; an unsatisfied item expires at equality, while a completed pre-deadline quorum is retained with lateness facts.
4. Use closed immutable queue/response/disposition artifacts and a private confined locator manifest. Bind exact source, subject, context and policy hashes. Require fresh complete original closure before a promotion-ready disposition bundle. Core merge/status/HTML commands never apply domain changes. Default projections show bounded IDs/hashes/reasons/counts; prose, rationale, names, paths and evidence bytes are omitted. Rationale remains private immutable response evidence.
5. Use existing typed readers, strict JSON, SHA-256, UUID and confined no-replace publication. Freeze typed fingerprint encodings and vectors before implementation. Apply the finite original byte/file/depth caps and [capacity refinement](/private/tmp/forge-f12-portable-review-capacity-refinement-v1/proposed-capacities.json) before growth, with complete refusal on exhaustion and one cooperative work ledger. No new dependency is proposed.

The [full design](/private/tmp/forge-f12-portable-review-queue-design-v1/design.md) and [decision cards](/private/tmp/forge-f12-portable-review-queue-design-v1/decisions.md) retain the complete semantics.
