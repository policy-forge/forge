# Maintained headless client extension

The maintained client now has a locally tested extension for fourteen additional workspace operation families. The root-owned candidate run passed all sixteen existing check groups against a preserved default-feature release executable built with `--release --locked --offline` from Rust source at `aa73a72349bce9f61905ceaea02f934c01e3d6b3`. The candidate scripts were frozen separately; this local result is not release-candidate, hosted, browser, OS-confinement, attempted-egress or human acceptance.

From the repository root, run the standard-library controls or the actual client against a supplied Forge executable:

```sh
python -B scripts/test_workspace_client_extension.py
python -B scripts/test_workspace_client.py --forge /path/to/forge --receipt /new/private/client-receipt.json
```

The controls use a fake HTTPConnection and clock with synthetic private files. They launch no Forge process or network socket. The actual client launches machine-mode loopback workspaces and prepares, explicitly commits and registers synthetic resources in temporary directories. It requires a new receipt destination and preserves an existing destination. Its public receipt retains fixed check names and operation outcome counts; private bodies, excerpts, fixture paths and capabilities are not included.

The extension exercises twelve read/compute families: session and config status; registered resource metadata and validation; selected/all validation; mapping checks and proposed draft validation; committed applicability report; queue counts, complete pages and reason filters; provenance pages and exact whole-line excerpts. Two further families inspect the accepted conversion result and its still-unconsumed preview in the creating session. A reopened session must refuse those old session-local IDs. These are the documented [workspace API](../api/forge-workspace-v1.openapi.yaml) operations, without new routes or receipt schemas.

A separate two-control fixture uses supported prepare/preview/confirmed-commit workflows and registers the genuinely generated applicability report as the seventh resource. Synthetic reviewer values are development data, not human judgments. The original six-resource workflow remains intact. A valid eighth source is registered normally, then deliberately changed to invalid UTF-8 while stopped. Minimal valid/invalid config and a valid scope-rationale change also happen while stopped. The stale report preserves its historical classifications and unmatched scope fingerprint. Seven additional sessions must exit naturally and refuse a real query after closing; with the two original sessions this gives nine post-close transport observations, not process-tree or OS-denial proof.

Pages use fixed `page_size=1`, complete denominators, stable versions, bounded cursors and unique route-specific primary IDs. Resource metadata binds already captured file names, sizes and SHA values; response paths are never opened. Present provenance fingerprints must be lowercase SHA-256 hex. Source-reference fingerprints retain raw-resource correlation; mapping subject fingerprints can represent derived inventory identities and need not equal a whole-file hash. Their semantics are not independently recomputed by this minimum prerequisite. Excerpts still bind exact current source bytes, UTF-8 whole-line spans and truncation.

The extension delegates at most 200 requests under one finite monotonic 300-second pass fence. It refuses a new delegated call at or after the deadline and a late return cannot earn pass. The observed local run used 170 delegated calls. The complete additional fixture separately bounds its actual request delta, including seven shutdown calls and seven post-close probes, at 200. The whole client retains the shared 10,000-attempt cap. Existing request, startup and cleanup ceilings remain 30, 20 and 3 seconds respectively; this is not syscall/parser preemption or a hard 300-second whole-process wall-clock guarantee. Private fixture capture is flat and complete: at most sixteen regular nonlink files, one MiB each, sixteen rows/pages and cursors of at most 512 characters. These small fixture limits are not workspace-capacity acceptance.

Two original runs failed honestly at an overstrong provenance fingerprint assertion; the first also had a later collector error. Their failed receipts remain preserved. Root v2 corrected that assertion and the missing queue/provenance ID checks, adding three controls while preserving all 31 earlier control bodies. The two separate source findings, APIF-01 and APIF-02, do not become approval of the successor merely because tests pass. The known absent-report documented 404/implemented 422 and consumed-preview documented 410/implemented 409 differences are retained separately, not normalized to obtain a pass.
